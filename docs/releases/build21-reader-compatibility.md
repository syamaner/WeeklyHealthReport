# Preserve released build21 alongside workout distance export

This integration preserves the nutrition implementation already distributed in internal build 0.1.1 (21) while adding the independently reviewed workout-distance reader from PR #185. It introduces no new nutrition feature and does not import later unpublished work.

## Architecture gate

The nutrition domain retains source identity, unknown nutrients, explicit evidence review and versioned confirmation. Application services orchestrate source selection, extraction, applicability and confirmation. OpenRouter, public-page capture and Keychain remain infrastructure adapters; presentation requests explicit review through application interfaces. The HealthKit adapter remains read-only and passes plain values to the workout domain. The two flows meet only at existing app composition and local presentation. Health records and saved history must never enter provider requests. No live provider calls, credentials or personal Health stores are required by validation; native acceptance uses only the authorised synthetic simulator store.

The volatile boundaries are provider transport, page capture and HealthKit access. Closed invariants include source binding, canonical JSON admission, explicit nutrition review, unavailable values, workout schema7/enrichment2, and distinct accepted versus native distance. Contract tests must preserve these independently. This import does not change production workout files.

## Validation and release boundary

The integration requires independent diff review, FoodLedger contract tests, the complete combined simulator suite, static analysis, and the retained thirteen-case native consumer harness assembled from this exact source. That harness reads only previously authorised synthetic simulator workouts; it makes no new Health writes. Protected PR and exact-main CI are required before a compatible release. The reviewed public privacy policy must be published and verified at the existing App Store Connect URL.

Build20 was superseded without upload. Build21 is an existing separate nutrition release; this source integration is not itself a new distributed build. A new build number must be checked live before any future upload. Reader Health3 support must be available before or alongside the producer that writes Health3. Physical-device comparison, same-workout re-export and independent nutrition acceptance remain pending.
