# Native food search clarity v1

The normal search flow follows the existing native design baseline in food-log-ux-design-plan.md and intake-screen-design-v1.md: grouped forms, system typography/colours, standard navigation and sheets, 44-point targets, Dynamic Type and accessible labels. There is no separate visual theme or provider console.

One submitted search publishes local matches first. Enabled services run only under the existing coverage/key policy. A single status stays above the scrollable results and names the current source. It remains after completion and distinguishes no extra matches, unsupported nutrition, unavailable services and a stopped search. Search details list only actual completed/pending stages; unused services are “Not searched”. New rows retain their IDs/order, are labelled “Added online” and can be reached through “See added matches”. Selecting a row or editing the query prevents later arrivals from replacing that choice or restoring stale status.

Rows contain a food name, brand when available, source/basis and material caution. Raw enums, source identifiers, lexical scores, matching-token dumps and generic policy paragraphs do not fill the normal list. Greek-style alternatives, literal versus fat percentages, uncertain requested preparation and representative recipe weight limits remain honest. Deeper food/nutrition references stay in the existing review flow. Web citations and provider suggestions remain together on the transient Web sources screen. Developer diagnostics/manual discovery are available only inside Search settings when the advanced setting is enabled.

Application orchestration supplies accepted-stage reports containing genuinely added candidate IDs after validation/deduplication, failures and source-review outcomes. Presentation formats these facts. Providers, coverage escalation, source admission, provenance, domain schema, nutrient arithmetic, quantities and explicit save policy are unchanged. No additional search, retry, credential access, analytics or storage is introduced.

Validation evidence and native rendering are retained in the primary checkout under Tools/LocalHybridSearchEvaluation/diagnostics/search-ux-v1/. The interactive preview is illustrative, not a food-provider result or release evidence. Device/VoiceOver usability and user acceptance remain separate from simulator/contract validation. TestFlight build 14 does not contain this local change.
