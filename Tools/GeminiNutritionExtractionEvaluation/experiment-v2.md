# Candidate v2 — extraction and fetched-document fallback

Architecture gate (before collection): keep v1 inputs, scorer and collector unchanged. A new adapter imports their credential/transport/projection capabilities. An unauthenticated fetch adapter accepts only frozen development URLs, HTTPS and same-host redirects, with byte/text/time limits. It converts HTML to line-numbered visible text, retaining navigation and table columns; it removes script/style/template content without selecting nutrient facts. Raw HTML is hashed and discarded. Source text stays in an owner-only temporary directory. Pure v1 scoring still owns identity, value, operator, basis and preparation; v2 adds line-reference completeness and portion checks. No app or admission changes.

Frozen gold is unchanged. Prompt v2 explicitly specifies `operator =` for declared values and clarifies that `source_record` denotes the selected record, not exact nutrition of a user's meal. Request schema descriptions reinforce these meanings. No null-to-equality repair is allowed. Fetched document text is untrusted evidence and cannot override the instruction. New file hashes, source-document hashes and a planned-call list are frozen before Gemini collection.

Development plan: 12 panel calls plus up to 8 fetched-document calls (four source URLs reused across related questions), at most 20 extraction POSTs. Failed page retrieval remains an uncompleted planned case; it cannot silently disappear from the denominator. No provider retries. A separate two-call Google Search discovery probe uses the user's exact descriptive food phrases. Source selection is independently reviewed; any continuation represents a simulated evaluation choice, not user approval to save food. End-to-end success requires source identity, evidence, nutrition basis and portion support through the same chosen source.

Advancement: all development extraction tasks and independent evidence checks must pass before selecting this candidate or running the four reserved holdouts. Discovery failures are reported separately. No holdout call is authorised by this document alone; the user's instruction to proceed covers it conditionally after a stable development result. This turn is capped at 22 Gemini POSTs including discovery. Any further candidate is a later experiment, not an automatic retry.
